# クラブ順位（上位30）の取り込み

アプリ（Kagaribi Stat Hub）はネットにつながったときに
`https://raw.githubusercontent.com/satsuki19980613/kagaribi-club-data/main/clubs.json` を読み、
スタッツビューの「クラブ順位 · 上位30」に出す。この手順で、その clubs.json に 1 節ぶん足す。

## 1. ポストを受け取る

- クラウドのセッションからは X（x.com）を読めない。ユーザーに、集計ポストの**スレッド全体**をコピペしてもらう（スクショでもよい）。
- 1 行の形: `順位(前節の順位) 累計 +その節の得点 メダル クラブ名`（例 `1(1) 138 +50 🥇 SB from リンプして時雨`）。
  見出しの `シーズン31 第3節` からシーズンと節を読む。名前・時刻・いいね数などの行は無視される。
- スクショのときは、画像から上の形の行に書き起こしてから次へ進む（クラブ名は 1 文字ずつ確かめる）。
- 30 クラブがスレッドの複数のポストに分かれていることがある。全部そろっているか数える。

## 2. データ用リポジトリを用意する

1. `add_repo`（owner `satsuki19980613`, repo `kagaribi-club-data`, access `push`）でこのセッションに足す。
2. `git clone` する（既にあれば `git pull`）。置き場所は Kagaribi-Stat-Hub の隣（例 `/home/user/kagaribi-club-data`）。
3. Kagaribi-Stat-Hub で `npm ci`（node_modules が無ければ）。

## 3. 読んで確かめる（まだ書き込まない）

貼られた文章をスクラッチパッドに `paste.txt` として保存し、Kagaribi-Stat-Hub で:

```sh
npm run --silent ranking -- --file ../kagaribi-club-data/clubs.json --in <scratchpad>/paste.txt --dry
```

- シーズン・節が読めないときは `--season 31 --round 3` を足す。
- 第N節は、そのシーズンの N 番目の開催日（アプリのシーズン設定で決まる）。
- 出力の「読めなかった行」「確認してほしいこと」を 1 つずつ見る:
  - クラブ数が 30 でない → スレッドの続きが欠けていないか、ユーザーに聞く。
  - `前節 X + Y ≠ Z` や前節の順位の食い違い → たいていはクラブ名の表記ゆれ（全角・半角・空白・絵文字）。
    前節のデータ（clubs.json）の表記に paste.txt を合わせて読み直す。本当に元のポストの数字が合わないなら、そのままにしてユーザーに伝える。
  - 「前節のデータがない」→ 前の節を取り込み忘れていないか、ユーザーに聞く（抜けた節はグラフが途切れるだけで、壊れはしない）。
- エラーが出たら書き込まれない。直してから読み直す。

## 4. 書き込んで送る

1. `--dry` を外して同じコマンドを実行する（同じ節が既にあれば置き換わる）。
2. データ用リポジトリで `git add clubs.json && git commit -m "S31 第3節"` のようにして、**main に push** する。
   アプリは main を読むので、main に入らないと反映されない。このリポジトリはデータ専用で、main へ直接 push することはユーザーが了承している。
   セッションの決まりで main に push できないときは、指定されたブランチに push して PR を作り、そのままマージする。
3. GitHub の配信のキャッシュがあるので、アプリに出るまで最大 5 分ほどかかる。

## 5. 報告する

- シーズン・節、クラブ数、燎の順位（圏外ならそう書く）、1 位のクラブと累計。
- 確認してほしいことが残っていれば、その内容。
